## 0. 목표와 마감

- **목표**: 현대자동차그룹 차량용 앱 개발 공모전 가산점용 최소 시제품
  1. Pleos Connect 에뮬레이터에서 동작하는 APK
  2. 소스와 APK가 올라간 GitHub 저장소
  3. 버추얼 콘솔로 차량 신호를 바꾸며 앱이 반응하는 60초 화면 녹화
- **마감**: 2026-11-14 (11/15 수정 제출 전 하루 여유)
- **앱 한 줄 설명**: 브레이크·방향지시등·와이퍼·뒷좌석 열선 같은 차량 신호에 맞춰 이야기가 바뀌는, 뒷좌석 아이를 위한 차량용 이야기 앱

## 1. 작업 규칙 (LOOP)

- "완료" 선언 금지. 각 마일스톤은 **검증 항목을 실제로 실행해 통과한 뒤**에만 다음으로 넘어간다.
- 마일스톤이 끝날 때마다 아래 완료 카드를 출력한다.
  ```
  작업/산출물:
  검증: (무엇을 실행해 확인했나)
  판정: 통과 / 실패 항목과 사유
  미확인·남은 것:
  ```
- 같은 항목이 3회 실패하면 멈추고 사용자에게 묻는다.
- **위험 결정 정지**: 범위 확대, 구조 변경, 외부 서비스 추가, 파일 대량 삭제는 먼저 묻는다.
- **SDK 함수 이름을 지어내지 않는다.** 반드시 공식 샘플과 문서에서 실제 이름을 확인해 사용한다.
- API 키, 토큰, 개인 이름, 연락처를 코드·커밋·README에 넣지 않는다. (이번 시제품은 외부 API를 쓰지 않으므로 키가 필요 없다.)

## 2. 범위

### 포함 (이번 시제품)
| 기능 | 설명 |
|---|---|
| 차량 신호 읽기 | 브레이크 페달, 드라이브 모드(주차/주행), 방향지시등, 와이퍼 모드, 뒷좌석 열선 상태, 도어 열림, 안전벨트 경고 |

- 공식 문서
  - Vehicle SDK 개요: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/
  - Capability 확인: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/check-capability
- 패키지명(제안): `com.zestfulpulse.storydrive`

## 4. 사건 코드와 신호 매핑

| 사건 코드 | 발생 조건 | 처리 |
|---|---|---|
| `START` | 앱에서 "이야기 시작" 누름 (정차 중) | 오프닝 장면 |
| `STOP` | 주행 중 브레이크로 정지 상태 진입 | 정차 장면 |
| `GO` | 정지 후 다시 출발 | 출발 장면 |
| `TURN_LEFT` / `TURN_RIGHT` | 방향지시등 켜짐 | 회전 장면 |
| `RAIN_ON` | 와이퍼 꺼짐 → 켜짐 | 비 시작 장면 |
| `RAIN_HARD` | 와이퍼 고속 | 굵은 비 장면 |
| `RAIN_OFF` | 와이퍼 꺼짐 | 비 그침 장면 |
| `WARM` | 뒷좌석 열선 꺼짐 → 켜짐 | 용의 숨결 장면 |
| `DOOR_OPEN` | 문 열림 | **이야기 멈춤** + 쉬는 시간 안내 |
| `BELT_WARN` | 안전벨트 경고 | **이야기 멈춤** + 벨트 안내 |
| `RESUME` | 문 닫힘 또는 벨트 정상 | 이어가기 장면 |
| `IDLE` | 25초 동안 사건 없음 | 이어지는 이야기 장면 |

**처리 규칙**
1. 우선순위: `BELT_WARN`·`DOOR_OPEN` > 나머지. 안전 사건은 지금 읽는 문장을 즉시 끊는다.
2. 같은 사건은 8초 안에 다시 오면 무시한다 (깜빡이 반복 등).
3. 다른 장면을 읽는 중에 일반 사건이 오면 큐에 넣고 현재 문장이 끝난 뒤 읽는다. 큐는 최대 2개, 넘치면 오래된 것부터 버린다.
4. 같은 사건의 장면 블록이 여러 개면 직전과 다른 것을 고른다.
5. 지원되지 않는 신호(capability 없음)는 조용히 제외하고 화면 목록에 "이 차량에서는 사용 안 함"으로 표시한다.

## 5. 장면 블록 (assets/scenes.json 초안)

`{아이1}`, `{아이2}`는 앱 안에서만 채운다. 시제품에서는 기본값 "대장", "부대장"을 쓴다.

```json

    "START": [

      "준비됐어? 불꼬가 날개를 활짝 폈어. 구름 섬으로 출발!"
    ],
    "STOP": [
      "어? 구름 신호등이 빨간색이야. 불꼬도 잠깐 구름 위에 앉아서 쉬자. 다 같이 하나, 둘, 셋!",
      "멈춤! 불꼬가 날개를 접었어. 숨 한 번 크게 쉬고 기다려 보자."
    ],
    "GO": [
      "초록불이다! 불꼬가 다시 하늘로 날아올라!",
```

## 6. 화면 (이야기 재생 1개)

참고: 기획서의 화면 시안 1번을 단순화. 가로형, 큰 글씨.

- 상단: 앱 이름 "스토리드라이브"
- 왼쪽: 지금 읽는 문장 (큰 글씨), 그 위에 작은 글씨로 "불꼬와 구름 섬 가는 길"
- 오른쪽: **"차가 들려준 신호"** 목록. 최근 반영된 사건을 위에 표시하고, 방금 반영된 항목은 주황색으로 강조
- 아래: "이야기 시작"(정차 중에만 활성), "이야기 잠시 멈추기"
- 색: 하늘 `#CFE4F2`, 종이 `#FFF8EC`, 잉크 `#233050`, 주황 `#F27A2E`

## 7. 마일스톤과 검증

### M0. 환경 준비
- 할 일: Android Studio, Pleos 에뮬레이터 AVD 생성, 공식 샘플 빌드·실행, 새 프로젝트 생성, `.gitignore`(Android 표준 + `local.properties` + 키 파일 패턴)
- 검증: 공식 샘플이 에뮬레이터에서 실행되고 차량 API 목록이 보임 / 새 프로젝트 빈 화면이 에뮬레이터에서 뜸

### M1. 음성 합성 검증 ⭐ 가장 먼저
- 할 일: 버튼을 누르면 한국어 문장 1개를 Pleos TTS(ON_DEVICE)로 읽는 화면 (실패 시 녹음 파일 재생으로 전환)
- 검증: 에뮬레이터 스피커로 한국어가 실제로 들림, 로그에 초기화 성공 기록
- **실패 시**: 멈추고 사용자에게 보고. 대안(미리 녹음한 음성 파일 재생)으로 갈지 결정받기

### M2. 차량 신호 읽기
- 할 일: 공식 샘플 방식으로 Vehicle 객체를 얻고, 4장 신호마다 capability 확인 → 상태 변화 구독. 신호 변화를 화면 로그에 표시
- 검증: 버추얼 콘솔에서 브레이크, 방향지시등, 와이퍼, 열선, 도어, 벨트를 각각 바꿀 때 로그가 찍힘. 지원 안 되는 항목은 "사용 안 함"으로 표시
- 기록: 실제로 사용한 SDK 클래스·함수 이름을 `docs/SDK_NOTES.md`에 정리 (README와 2차 PT 설명용)

### M3. 사건 변환과 이야기 재생
- 할 일: 4장 규칙대로 사건 코드 생성, 5장 JSON을 불러와 장면 선택, 음성 재생, 큐·중복 무시·우선순위 적용
- 검증: 단위 테스트(사건 변환, 8초 중복 무시, 안전 사건 우선, 큐 최대 2개) 통과 + 에뮬레이터에서 브레이크→정차 장면, 깜빡이→회전 장면이 실제로 들림

### M4. 화면
- 할 일: 6장 화면 구현, 사건 목록 강조
- 검증: 신호를 바꿀 때 화면 목록과 문장이 함께 바뀜. 앱 실행 10초 이내, 버튼 반응 2초 이내 (Pleos 앱 심사 기준)

### M5. 안전 동작
- 할 일: 벨트 경고·문 열림 시 즉시 멈춤과 안내, 해제 시 이어가기, 주행 중 "이야기 시작" 비활성
- 검증: 버추얼 콘솔로 각 상황 재현 시 기대 동작 확인

### M6. 패키징과 제출물
- 할 일: 릴리스 APK 빌드, GitHub 공개 저장소에 소스 푸시, GitHub Releases에 APK 업로드, README 작성(아래 8장)
- 검증: 깨끗한 환경에서 저장소를 받아 빌드 성공 / Releases에서 APK 다운로드 가능 / 저장소 전체에서 키·개인정보 검색 결과 없음

### M7. 선택 (시간이 남으면)
- NaviHelper로 도착까지 남은 시간을 읽어 5분 전 마무리 장면 추가

## 8. README 초안 (저장소 루트)

```markdown
# 스토리드라이브 (StoryDrive) 시제품

브레이크, 방향지시등, 와이퍼, 뒷좌석 열선 같은 차량 신호에 맞춰 이야기가 바뀌는
뒷좌석 아이를 위한 Pleos Connect 차량용 이야기 앱의 시제품입니다.
현대자동차그룹 차량용 앱 개발 공모전 출품작입니다.

## 동작 방식
1. 신호 수집: Vehicle SDK로 차량 상태를 구독 (지원 여부는 capability로 확인)
2. 사건 변환: 신호 변화를 STOP, TURN_RIGHT, RAIN_ON, WARM 같은 사건으로 변환
3. 이야기 엔진: 사건에 맞는 장면 블록을 골라 이어 붙임
4. 안전 장치: 안전벨트 경고나 문 열림 시 즉시 멈춤
5. 출력: Pleos 음성 합성(ON_DEVICE, 실패 시 녹음 파일)으로 읽고 화면에 문장 표시

## 실행 방법
1. Pleos Connect 에뮬레이터 설치 (공식 가이드 링크)
2. 이 저장소를 Android Studio로 열고 실행, 또는 Releases의 APK 설치
3. 버추얼 콘솔에서 브레이크, 방향지시등, 와이퍼, 열선 상태를 바꿔 이야기 반응 확인

## 사용 SDK
Vehicle SDK (Vehicle State). 상세는 docs/SDK_NOTES.md

## 개인정보
아이 목소리를 녹음하거나 저장하지 않습니다. 이 시제품은 외부 서버와 통신하지 않습니다.
```

## 9. 60초 에뮬레이터 녹화 대본 (M6 이후)

Android Studio 에뮬레이터 화면 녹화 기능으로 녹화하고, 버추얼 콘솔 창이 같이 보이게 배치한다.

| 시간 | 버추얼 콘솔 조작 | 기대 반응 |
|---|---|---|
| 0~8초 | 기어 P, "이야기 시작" 누름 | 오프닝 문장 음성 |
| 8~16초 | 기어 D | 출발 장면 |
| 16~24초 | 브레이크 밟음(정지) | 정차 장면 "하나, 둘, 셋" |
| 24~30초 | 브레이크 해제 | 출발 장면 |
| 30~38초 | 오른쪽 방향지시등 | 회전 장면, 화면 목록 주황 강조 |
| 38~46초 | 와이퍼 켜기 | 비 장면 |
| 46~54초 | 뒷좌석 열선 켜기 | 용의 숨결 장면 |
| 54~60초 | 뒷좌석 문 열기 | 이야기 멈춤 + 쉬는 시간 안내 |
